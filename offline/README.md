# IT Trivia Challenge: offline edition

A single self-contained file, `index.html`, for demo tables and classrooms with no Wi-Fi.
No server, no API key, no install. Five IT areas, each a separate 5-question quiz, launched
from a spin wheel.

## Play

1. Copy `index.html` anywhere (USB stick, laptop desktop, shared drive).
2. Double-click it. It opens in the default browser from a `file://` URL and works fully offline.
3. **SPIN** picks an area at random and starts its quiz. Tapping a slice starts that area directly.
4. After 5 questions the score screen shows; **Spin again** (or 30 s of idling) returns to the wheel.

Keyboard: `1`–`4` answer, `S` spins, `Esc` goes back to the wheel. Works with a touch screen, mouse or keyboard.

For a kiosk feel: Chrome `--kiosk file:///path/to/index.html` (or press F11), or iPad Guided Access.

## Phones and tablets

- **Android**: opening `index.html` from the Files app in Chrome works as-is.
- **iPhone/iPad**: an `.html` file opened from Files, AirDrop or Mail renders in Quick Look, which does
  **not** run JavaScript, so the wheel will not work that way. Serve it from a laptop instead:

  ```bash
  cd offline
  python3 -m http.server 8080          # any laptop with Python; Ctrl+C to stop
  ```

  Put the phones on the laptop's hotspot (or the same Wi-Fi) and open `http://<laptop-ip>:8080/`.
  Find the laptop IP with `ipconfig` (Windows) or `ifconfig` / `ip a` (macOS/Linux).

Nothing in the page ever leaves the device. `index.html` is the only file you need to distribute.

## Question bank

Questions live in `sets/*.json` (one file per 25-question set, 5 per area, generated by the live
app's Gemini prompt at the `easier` difficulty) and are embedded into `index.html` by a script.
The raw JSON stays in the repo so a wrong fact can be fixed by hand and re-embedded.

```bash
node offline/fetch-set.mjs           # POST https://trivia.benlamb.net/api/questions → sets/easier-NNN.json
node offline/build-bank.mjs          # validate every set and embed them into index.html
node offline/build-bank.mjs --check  # exit 1 if index.html is stale or a set is invalid
```

Each set adds 5 more questions per area; the game deals 5 per quiz and cycles through the whole pool
before repeating any, so more sets means more variety for back-to-back players. Options are
reshuffled every deal. `fetch-set.mjs --difficulty normal` saves other tiers, but only
difficulties listed in `ACTIVE_DIFFICULTIES` inside `index.html` are used by the game.

The validator rejects a set unless it has exactly 25 questions, 5 per area, 4 distinct options
each, and a `correctAnswer` that exactly matches one option (the quiz compares by string equality).

## Tuning

Everything adjustable is at the top of the inline script in `index.html`:

| Constant | Default | Meaning |
|---|---|---|
| `TIMING.spinMs` | 4200 | wheel animation length |
| `TIMING.settleMs` | 500 | pause after the wheel stops before the quiz opens |
| `TIMING.revealMs` | 1500 | how long the green/red answer reveal stays before the next question |
| `TIMING.resultsIdleMs` | 30000 | score screen auto-returns to the wheel |
| `TIMING.quizIdleMs` | 90000 | an abandoned quiz returns to the wheel |
| `QUESTIONS_PER_QUIZ` | 5 | questions per area quiz |
| `AREAS[i].lines` | | the two-line label on each wheel slice (`name` must stay the API category string) |

## Tests

```bash
node --test 'offline/test/*.test.mjs'
```

The tests import happy-dom from `web/node_modules`, so run `npm ci` in `web/` first. They cover the
bank validator, the wheel geometry (1000 seeded spins must land on the chosen slice), question
dealing, a full play-through, keyboard handling, and a static guard that the file has no external
URLs, `fetch`, or ES modules. Use the explicit glob: `node --test offline/` would execute every file
in the directory as a script.

## Files

| Path | Role |
