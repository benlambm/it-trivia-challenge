# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this directory is

`/opt/trivia-app/` — the **monorepo** for `trivia.benlamb.net`. Both the React frontend (`web/`) and the Node/GenKit backend that calls Gemini (`api/`) live here together. nginx serves the built frontend out of `/var/www/trivia.benlamb.net/` (artifacts only — no source there). The backend runs as a systemd-managed Node service listening on `127.0.0.1:3000`, reverse-proxied by nginx under `/api/`.

```
/opt/trivia-app/                    ← this repo (single source of truth)
├── .github/workflows/deploy.yml    ← auto-deploys on push to main (SSH from GH runner → here)
├── .gitignore                      ← excludes api/.env, node_modules/, dist/, /index.html, etc.
├── CLAUDE.md
├── api/                            ← Node 24 / GenKit backend
│   ├── index.js                    ← all three /api/* handlers + zod schemas + Gemini calls
│   ├── package.json, package-lock.json
│   ├── .env                        ← GOOGLE_GENAI_API_KEY, mode 0600, owner trivia-api:trivia-api
│   │                                 NEVER COMMITTED — gitignored. Server-only.
│   ├── .env.example                ← committed template
│   └── node_modules/               ← gitignored; regenerated by `npm ci`
└── web/                            ← Vite 8 + React 19 + TypeScript frontend
    ├── index.html                  ← Vite dev/build template referencing /index.tsx
    ├── App.tsx, index.tsx, types.ts
    ├── components/*.tsx
    ├── services/geminiService.ts   ← name is historical; now calls /api/*, not Gemini directly
    ├── package.json, package-lock.json, vite.config.ts, tsconfig.json
    ├── dist/                       ← `vite build` output (gitignored)
    └── node_modules/               ← gitignored

/var/www/trivia.benlamb.net/        ← served artifacts ONLY (no source, no .git)
├── index.html                      ← built; copied from web/dist/ at deploy time
├── assets/index-<hash>.js
├── index.html.prev                 ← previous deploy, one-shot rollback target
└── assets.prev/

/etc/systemd/system/trivia-api.service   ← references /opt/trivia-app/api/
```

App is "Brightpoint IT Trivia Challenge" — originally exported from Google AI Studio.

## Where the Gemini API key actually lives

**Only** in `/opt/trivia-app/api/.env` (`GOOGLE_GENAI_API_KEY=...`, mode 0600, owner `trivia-api:trivia-api`). The file is **gitignored** and must stay that way — nothing committed to GitHub should ever contain a key. To rotate: edit the live file, `systemctl restart trivia-api`, no rebuild needed.

Verify the client bundle stays clean after every deploy (the GH Actions workflow does these checks too and fails the run if either matches):

```
grep -c '@google/genai' /var/www/trivia.benlamb.net/assets/*.js          # must be 0
grep -oE 'AIza[0-9A-Za-z_-]{35}' /var/www/trivia.benlamb.net/assets/*.js # no matches
```

If either ever returns a hit, **something has gone wrong** — the SDK or a key has leaked back into the client.

## The two services that make this site work

| Component | Source | Served from | Listens | Managed by |
|---|---|---|---|---|
| Static React SPA | `/opt/trivia-app/web/` | `/var/www/trivia.benlamb.net/` | nginx :443 | nginx |
| `trivia-api` (Node/GenKit Gemini proxy) | `/opt/trivia-app/api/` | (runs in place) | `127.0.0.1:3000` | `trivia-api.service` (systemd) |

nginx routes:
- `/` → static files in `/var/www/trivia.benlamb.net/`
- `/api/` → `proxy_pass http://127.0.0.1:3000/api/`
- `/src/` → 404 (legacy deny block; defense-in-depth — see "Critical invariant" below)

Backend logs: `journalctl -u trivia-api -f`. Restart after editing `api/index.js` or `api/.env`: `systemctl restart trivia-api`.

## The /api/ contract (load-bearing — frontend depends on shape)

The backend exposes exactly three endpoints:

- `GET /api/health` → `{ "status": "ok" }` — liveness only, no Gemini call
- `POST /api/questions` → `{ "questions": [{ category, text, options[4], correctAnswer }, ...25 items] }` — the frontend assigns `id` and re-shuffles `options` client-side after receiving this
- `POST /api/results` body `{ score: int, total: int }` → `{ title, evaluation, motivation }` — frontend wraps with `score`/`totalQuestions`

The shape is preserved across the frontend boundary by `web/services/geminiService.ts`, which exports `generateQuestions()` and `generateGameResults(score, total)` with the same signatures the original AI-Studio-generated code had. Changing the wire format means updating BOTH `api/index.js` (zod schemas + flows) AND `web/services/geminiService.ts` (TS interfaces + the consumer of the JSON).

Model used by the backend: **`gemini-flash-latest`** (auto-tracks Google's newest Flash). To pin a specific version (e.g. `gemini-2.5-flash`), edit the `MODEL` constant at the top of `api/index.js` and restart the service.

## Critical invariant: source must never be web-accessible

Source code (web/, api/, .env) lives at `/opt/trivia-app/`, which nginx does not serve. Structurally, source cannot leak through the web. Belt + suspenders: the legacy nginx deny block on `/src/` is kept as defense-in-depth in case anyone ever points the doc root somewhere it shouldn't be:

```nginx
location ^~ /src/ {
    deny all;
    return 404;
}
```

`^~` ensures the prefix beats regex location blocks. Verify after any nginx edit:
```
curl -sI https://trivia.benlamb.net/src/.env.local   # must be 404
curl -sI https://trivia.benlamb.net/api/.env         # must be 404 (api proxy doesn't expose the file)
curl -sI https://trivia.benlamb.net/                 # must be 200
curl -sI https://trivia.benlamb.net/api/health       # must be 200
```

## Build & deploy

**Auto-deploy** on push to `main` via `.github/workflows/deploy.yml`. The GH Actions runner SSHes to the VPS as root (key + host pinned via repo secrets `DEPLOY_HOST` / `DEPLOY_SSH_KEY` / `DEPLOY_HOST_KEY`), `git reset --hard` to the pushed SHA, rebuilds `web/`, verifies the bundle is clean, rotates artifacts into `/var/www/trivia.benlamb.net/`, and rebuilds + restarts `trivia-api` **only if `api/` changed in this push** (via `git diff PREV..NEW -- api/`). Concurrency is set to `deploy-prod` with `cancel-in-progress: false` so overlapping deploys queue instead of stomping each other.

**Manual deploy (emergencies — when GH Actions is broken):**

```
# Frontend
cd /opt/trivia-app/web
npm ci
npm run build
cd /var/www/trivia.benlamb.net
rm -rf assets.prev; [ -d assets ] && mv assets assets.prev
cp -r /opt/trivia-app/web/dist/assets ./
[ -f index.html ] && mv index.html index.html.prev
cp /opt/trivia-app/web/dist/index.html ./

# Backend
cd /opt/trivia-app/api
npm ci --omit=dev
systemctl restart trivia-api
curl -fsS https://trivia.benlamb.net/api/health
```

Rollback: swap `assets.prev` back into `assets/` and `index.html.prev` back into `index.html`. For the backend, `git checkout <prev-sha> -- api/ && npm ci --omit=dev && systemctl restart trivia-api`.

## Why `web/index.html` and the deployed `index.html` look different

`web/index.html` is the **Vite template** — it references `/index.tsx` (the source entry). Vite reads it during `vite build`, replaces the `/index.tsx` `<script>` tag with a hashed bundle reference, and writes the result to `web/dist/index.html`. That output becomes the deployed `/var/www/trivia.benlamb.net/index.html`. **Never edit the deployed `index.html` by hand** — it will be overwritten on the next deploy. Edit `web/index.html` and rebuild.

## Browser-loaded dependencies (not bundled)

React is bundled by Vite into `dist/assets/*.js`. Tailwind is still loaded from `cdn.tailwindcss.com` (runtime JIT, no build step). If that CDN goes down, styling breaks — there's no vendored fallback for Tailwind.

**Local dev:** `cd web && npm run dev` → `http://localhost:5173` with `/api` proxied to `127.0.0.1:3000` (see `web/vite.config.ts`). Requires Node `^20.19.0 || >=22.12.0` for Vite 8.

**CI:** `.github/workflows/ci.yml` runs `npm test` and `npm run verify:bundle` in `web/` on Node 22.

## What NOT to do in this repo

- **Never commit `api/.env`** or anything containing `GOOGLE_GENAI_API_KEY=AIza...`. The .gitignore covers `.env` everywhere, but the rule of thumb: real secrets only exist on the server, never in git.
- **Never commit build output** (`web/dist/`, `web/node_modules/`, `api/node_modules/`). Already gitignored.
- **Never put files in `/var/www/trivia.benlamb.net/` by hand** other than what the deploy step rotates in. That directory is served on the public web.
